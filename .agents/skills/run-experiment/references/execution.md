# 実行環境、承認、役割分担

## Codex の役割分担

- 計画を確認してから着手する場合は、Codex のチャット欄で `/plan` を使う。`/goal` で開始する場合は、比較対象、入力、seed、予算、成果物、完了基準と、必要な役割分担を指定する。
- 複数エージェントで進める実験では、メインの Codex を監督役とし、実行担当と検証担当を各 1 体にする。監督役は条件と予算を確定し、担当への指示、進捗と中断の判断、最終集計を受け持つ。
- 実行担当は短い動作確認を行い、本計測を逐次実行する。ケースごとの配置、ログ、レポートを保存し、出力先、終了理由、失敗・未実行ケースを監督役に渡す。
- 検証担当は計測後に、入力と条件の一致、成果物の有無、保存済み配置から再計算した指標とレポートの一致を確認する。成果物の更新は実行担当が行い、検証担当は不一致や欠測をファイル名と根拠付きで監督役に報告する。監督役はこの検証結果を確認してから完了とする。
- 役割をプロジェクトに保存する場合は `.codex/agents/experiment_runner.toml` と `.codex/agents/result_reviewer.toml` に定義し、`/goal` で `experiment_runner` と `result_reviewer` を指定する。同時サブエージェント数を 2 にする設定は `.codex/config.toml` の `[agents]` に `max_concurrent_threads_per_session = 2`。サブエージェントは親セッションの権限を継承する。検証を権限で読み取り専用にする場合は、その権限を持つ別セッションを使う。 [Codex のサブエージェント設定](https://learn.chatgpt.com/docs/agent-configuration/subagents)

## Python 実行環境の確認

- 比較ケースの実行と検証には、可能な限り同じ Python 環境を使う。Windows ではまず `./.venv/Scripts/python.exe` の起動と `numpy`、`scipy`、`shapely` の読み込みを確認し、使用した実行ファイルのパスとバージョンを記録する。
- 本計測前に短い試行を行い、対象の手法が出力する配置・レポート・チェックポイントの保存を確認する。レイヤー割り当てでは重なり制約違反が 0 件であること、XY 配置では入力と候補の形状・重なりを比較できることも確かめる。Python 環境の変更後に根付き木ソルバーを使う場合は、本計測に使う Python で `-B -m unittest tests.test_solve_layers_tree` も実行する。
- `.venv` の起動に失敗した場合は、`pyvenv.cfg` に記録された Python 本体と、そのパスへのアクセス可否を確認する。ユーザー領域の Python 本体へのアクセスが通常のサンドボックスで制限された場合は、実行承認の手順に従う。過去の実験では、自動審査を通した実行で既存の `.venv` を使用できた。
- 2026-11-22 の確認では、既存の `.venv` の Python 3.11.5、NumPy 2.4.6、SciPy 1.17.1、Shapely 2.1.2 でテスト 28 件が成功した。`original.json` を使った動作確認は seed 0 で 100 試行完了し、最良解は 46 層、重なり制約違反は 0 件だった。

## 実行承認と一括実行

- サンドボックス外での実行が必要な場合は、Codex の自動審査（Auto-review）が利用可能なら、その経路で対象の実行を申請する。VS Code の Codex チャットでは権限メニューの **Approve for me**、CLI では `codex --approve-for-me` を使う。ローカル設定で指定する場合は `approval_policy = "on-request"` と `approvals_reviewer = "auto_review"`。管理された権限設定が優先する。 [権限モード](https://learn.chatgpt.com/docs/permission-modes)・[自動審査](https://learn.chatgpt.com/docs/sandboxing/auto-review)
- 長時間の比較では、入力、手法、seed、ケースごとの上限、全体の上限、保存先を確定してから、予定したケースを 1 本の実験スクリプトで逐次実行する。承認が必要なら、確定したスクリプトの起動を一括実行の単位として審査に出す。ケースごとの出力と終了状態は個別に記録する。
- 審査で拒否された場合は理由を記録し、許可された範囲で進められる準備や検証を続ける。一括実行の中断後は [中断と再開](../SKILL.md#中断と再開) の手順に従う。
