# 実験の実行と検証

着手前に [AGENTS.md](../../../AGENTS.md) の共通ルールと、実験対象に対応する設計資料を読む。本計測前は [実行環境と承認](references/execution.md) に従う。複数エージェントで進める場合も同資料を参照する。

## 実験条件

- 実行前に、比較する手法と変更点、入力、seed 一覧、試行ごとの予算、実験全体の予算、成果物を記録する。具体的な条件と完了基準は、その実験の依頼や `/goal` に従う。
- 手法だけを比較するときは、入力、XY 座標、頂点順序、重なり判定、正則化、評価式を揃える。定式化を比較するときも、各手法が最適化した値と、共通の評価式で再計算した値を記録する。
- 時間で比較する場合は、同じ予算で逐次実行し、実時間と実際の試行回数を記録する。試行回数を揃えて比較する場合は、共通の試行数上限と実際の終了理由を記録する。

## 実験コードの保存

- 新しい実験には固有の実験 ID を付け、実際に使う実行コードを `experiments/<実験ID>/run_experiment.py` として新規作成し、リポジトリに残す。実験 ID は出力側の `results/experiments/<実験ID>/` にも使う。
- 基準ソルバーと過去の実験コードは比較・再現用に保持する。既存の CLI や共通処理を再利用し、新手法に固有の実装は新しい実験ディレクトリ内のファイルに置く。
- 比較条件を変える新規実験には新しい ID と実行コードを用意する。同一条件での再試行や中断後の再開には保存済みのコードを使い、再試行の出力先を分ける。
- 最終報告には、実行に使ったコードのパス、リポジトリ直下から再実行できるコマンド、結果の保存先を記載する。

## 保存と再現性

- `original.json` などの原本データ、既存の表示用 JSON、過去の実験結果を上書きしない。新しい実験は `results/experiments/<実験ID>/<手法>/seed-<番号>/` のように、ケースごとに保存先を設ける。同じケースを再試行するときは別の保存先を使う。
- `solve_layers_tree.py` を実験で使う場合は、出力 JSON、`--initial-output`、`--checkpoint`、`--report` のパスをケースごとに指定し、実行ログも同じケースのディレクトリに保存する。 [ソルバーの引数](../../../solve_layers_tree.py#L925)
- 各ケースで入力の SHA-256、Git のコミットと使用した未コミット変更、実行コマンド、seed、実行時間、試行回数、終了理由を記録する。

## 結果の検証と報告

- 予定した条件で終了し、配置 JSON とレポートが揃ったケースを検証する。保存した配置と入力で頂点 ID・ハイパーエッジ ID・所属関係を照合し、配置から評価指標を再計算してレポートと突き合わせる。浮動小数点の照合には評価式に応じた許容誤差を使う。
- レイヤー割り当てでは XY 座標、所属頂点の順序、重なりペア集合が入力条件と一致し、レイヤーの重なり制約違反が 0 件であることを確認する。XY を変更する実験では、入力と出力で面ごとの形状と XY の重なりを比較し、その実験で定めた採否条件を確認する。
- レイヤー割り当てでは正規化した二乗目的値、高さ幅、柱の総長、実行時間、重なり制約違反数を集計し、整数解は使用レイヤー数も記録する。複数 seed の結果は個別の値と中央値、ばらつきを示す。未実行、失敗、中断も記録する。
- 可視化を比較するときは、同じ視点と表示倍率を使い、ポリゴンの輪郭、共有頂点の追いやすさ、柱の密集を確認する。

実験終了後の esa 投稿は [esa への実験報告](../report-experiment-to-esa/SKILL.md) に従う。

## 中断と再開

- 全体予算に達した場合や中断した場合は、検証済みの結果、途中集計、残りのケースを記録する。
- 再開時は検証済みのケースを飛ばし、途中で止まったケースは最初から実行する。現行ソルバーの `--checkpoint` は途中の最良解の保存に使う。
