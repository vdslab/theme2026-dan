# 2D と 2.5D の読み取りパイロット

対象頂点を含む面を4択で特定する課題を、平面表示・Qu 型入力順 first-fit・提案法で比較する。主な計測値は正答率と正答までの時間。各試行は、図を1枚表示する固定投影の課題とする。結果が解釈できる範囲は、この課題と使用した図に限る。

## 配布ファイルの生成

同じ公開入力から、入力順 first-fit と提案法の検証済みレイアウトを用意する。コマンドはリポジトリのルートで実行し、出力先は新しいパスを指定する。元データと検証済みレイアウトを別パスで指定する。

~~~powershell
python -B experiments/visnotes_reading_study_01/run_experiment.py --source <input.json> --first-fit <first-fit/layout.json> --proposed <proposed/layout.json> --output results/experiments/visnotes_reading_study_01/public-pilot
python -m http.server --bind 127.0.0.1 --directory experiments/visnotes_reading_study_01 8000
~~~

この準備コマンドは入力から重なりを独立計算し、XY・所属・頂点順序が両レイアウトで一致すること、異なる層への分離、入力順 first-fit の割り当てを照合する。正答は入力に記録された頂点の所属から決める。参加者にはブラウザーで [読み取り課題](http://127.0.0.1:8000/) を開いてもらい、生成物のうち `study.json` だけを設定する。`key.json` は採点時に使う。両者は刺激・正答・入力のハッシュにより対応付ける。ページは外部ライブラリを読み込まず、回答はネットワークに送らない。

## 刺激と割付

- 項目ごとに、2面以上に属する頂点を選び、その頂点を含む1面と、含まない近隣の3面を使用する。候補面、対象頂点、回答コードは3条件で固定する。研究対象の全体レイアウトから対応する面を切り出し、層を再探索しない。いずれかの投影で別の面の頂点がガイドから8 SVGピクセル未満になる候補は除く。正解位置A〜Dの出現数の差は最大1にする。
- XY表示は上面、2つの2.5D表示は方位45度・仰角35度の正射影とする。対象のXY位置を基準にして3条件に共通の座標領域と尺度を使用する。黄色の丸・ガイドは対象のXY位置を表示する。2.5Dのガイドは両条件の候補面の最低層から最高層までとし、正答面の所属層を特定する印を置かない。
- 既定では6項目を提示し、各条件を2項目ずつ割り付ける。1人に提示する対象頂点・候補面は重複しない。既定seedは 20261126。3条件の提示順6通りと項目の割付3通りを組み合わせた18枠では、各項目が各条件に6回ずつ、各条件が各ブロック位置に6回ずつ現れる。
- 18枠のパイロットでは同じ刺激で割付番号0〜17を事前に1回ずつ配る。少人数の試行では、使用した枠、実施環境、離脱を記録する。参加者には無記名コードを事前に渡し、条件名・正答・得点は提示終了まで見せない。図の角度と尺度は操作できない。操作説明に練習図を使う場合は、本番の面・頂点と重複しない別の図を使う。

## パイロットの実施と採点

運営側の必要な手続きと説明、記録の扱いを確定した上で、実行区分を「参加者パイロット」にする。同じ機器・ブラウザー・画面寸法で実施し、他の参加者と相談せず各自が回答する。参加者が用意できない場合は「動作確認」を使う。

計時は図を表示するフレームから回答確定まで。各項目は60秒で締め切る。「わからない」と時間切れは不正解として記録する。表示中にタブを隠す、ウィンドウのフォーカスを失う、または画面をリサイズするとその試行を中断扱いにする。記録は終了時または項目間に JSON で保存できる。

~~~powershell
python -B experiments/visnotes_reading_study_01/score.py --study <study.json> --key <key.json> --output <new-summary.json> <response-one.json> <response-two.json>
~~~

採点は、提示順と項目の照合後に、不完全セッション・中断試行・反応が150 ms未満の試行を集計対象から外す。全条件に少なくとも1件の有効試行がある参加者について、条件ごとの正答率と正答時間の中央値を算出する。要約は参加者別の値の中央値とし、提案法と各比較法との差を参加者内で集計する。正答時間の差は両条件に正答がある参加者を使い、その人数を記載する。集計には割付枠ごとの参加者数と、使用した画面寸法を含める。

ブラウザーの動作確認ログは `dry-run` として採点結果に参加者数を加えない。機械試験では提示・計時・保存・採点の動作を確認できる。人が正確に、速く読めるかは参加者の記録で検証する。
